# Remote configuration UI Implementation Plan

> **For agentic workers:** Use executing-plans to execute this plan, with test-first cycles and review checkpoints.

**Goal:** Let users safely configure the sync remote in the existing settings card.

**Architecture:** The existing owner-only HTTP route invokes a small validation and configEditor adapter. The browser renders a form and checks the effective configuration after saving, while preserving existing sync controls.

**Tech Stack:** Node.js, Cordis configEditor, React client bundle, node:test.

## Global Constraints

- Do not rewrite user YAML directly; preserve unrelated configuration fields.
- Reject embedded credentials; do not echo them in errors or logs.
- Report editor failures, override conflicts and profile-layer Pull overwrite risk.
- Verify against the installed DSH version in an isolated profile.

## Task 1: Establish host API and persistence behavior

- Inspect the installed configEditor source and run an isolated profile experiment; establish entry ownership, save target and plugin lifecycle.
- Test both save/restart and Pull overwrite behavior before promising persistence.

## Task 2: Host configuration endpoint

**Files:** `src/http.js`, `src/config.js`, `index.js`, `test/http.test.js`, a focused config validation test.

- Write tests that invoke a configuration POST, verify the editor receives `{ ...current, remote, branch, profile }`, and assert rejection of malformed or credential-bearing URLs, invalid branches/profiles and unavailable editors without leaking input.
- Run `node --test test/http.test.js` and confirm the new tests fail because the endpoint does not exist.
- Implement strict validation and a save adapter using `ctx.fiber.entry` and `ctx.get('configEditor').edit`; preserve remaining fields. Handle lifecycle and owner-only connection route according to the observed installed API.
- Rerun the focused tests and check they pass.

## Task 3: Form and feedback

**Files:** `client.js`, `test/client-feedback.test.js`.

- Write tests for initial empty config, edits, submission, save failure, reload and post-save effective-value verification; confirm they fail before implementation.
- Add localized remote, branch and profile fields and a save action. Never prefill a masked secret as an editable remote. Clearly show when the profile patch can be replaced by Pull.
- Run `node --test test/client-feedback.test.js` and confirm passing results.

## Task 4: Integration and release

**Files:** `README.md`, `README.en.md`, `CHANGELOG.md`, `package.json`, `package-lock.json`.

- Document UI setup, authentication and overwrite limitations; update version consistently.
- Run `npm test`, `npm run pack:check`, and `git diff --check`.
- In a disposable DSH profile, exercise first save, reload, restart, and Pull using a disposable remote. Verify both UI entry points and errors without modifying the user's remote.
- Review the complete diff, commit and push only after verification; report CI and any remaining limitations honestly.
