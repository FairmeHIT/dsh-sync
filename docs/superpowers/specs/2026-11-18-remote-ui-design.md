# 界面配置 Git 同步远端

## 目标
在“设置 → 配置同步”和插件详情的现有卡片中，允许用户配置 Git 仓库地址、分支和 profile，避免新机器手工编辑 YAML。继续保留状态、预览 Pull、应用 Pull 和 Push。

## 设计
卡片提供当前配置的非敏感展示、输入和保存操作，分支默认 main，profile 可留空以沿用现有自动检测。通过现有受保护的主机连接路由调用宿主逻辑，配置持久化使用 DSH configEditor 编辑当前插件 entry，不直接读写用户 YAML。保存前验证字段、拒绝 URL 中的密码、令牌或其他嵌入凭据，提示使用 Git 凭据管理器或 SSH。SSH 常规用户名 git 不视为密码。不得把凭据写入日志或响应。

保存时保留其他配置字段。高优先级覆盖、编辑器不可用、无效输入或保存失败均须显式报告，不得声称成功。配置变化可能重启插件及中断请求；实现需验证实际生命周期并向用户准确提示或重试，确保成功意味着持久化并重新读取生效配置。确认目标配置层不会因 Pull 被覆盖；若宿主编辑器只能写入受同步管理的 profile 层，明确告知该风险，不绕开编辑器直接重写用户 YAML。

## 验证
先写失败测试，覆盖输入校验、拒绝凭据、保留原字段、编辑器异常、保存重载和界面反馈；运行完整测试及打包检查。通过隔离 profile 验证首次配置、重启后的持久性、Pull 后的配置保留及界面操作，避免修改真实用户仓库。验证通过后按项目流程发布并说明部署及重启要求。
